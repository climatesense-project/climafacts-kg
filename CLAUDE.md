# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ClimaFactsKG builds an RDF knowledge graph linking climate-denial myths to scientific corrections, integrated with CimpleKG. It scrapes Skeptical Science, queries CimpleKG/ClimateSenseKG SPARQL endpoints, classifies claims against the CARDS misinformation taxonomy, and serves the result as `data/climafacts_kg.ttl` plus a live SPARQL endpoint.

## Commands

```bash
# Install (uv-managed; core install is lightweight, ML/eval deps are extras). Prefix commands below with `uv run` or activate .venv
uv sync                                           # core (+ dev group): collect/build/serve/process --classifier llm
uv sync --extra transformer                       # + process's default classifier (transformer, no API cost)
uv sync --extra matcher --extra transformer --extra eval  # + spaCy matcher, HF transformer classifier, eval/optimization pipeline
uv sync --all-extras

# Lint / format
ruff check .
ruff check --fix .
ruff format .

# Tests
pytest tests/
pytest tests/test_evaluators.py -v
pytest tests/test_matcher.py::TestCARDSMatcherClassify::test_unrelated_text_returns_default_code

# CLI (installed as `climafactskg` entrypoint -> climafactskg.cli:app; `eval` is a sub-app: run/context/report, which
# need the `eval` extra and print an install hint when it is missing; `eval-context`/`eval-report` remain as hidden 2.2.0 aliases)
climafactskg collect                                    # fetch raw data/URLs from all sources (steps run independently; a failed step does not stop the rest but makes the command exit 1, same for `process`)
climafactskg process --force --classifier transformer   # classify + populate intermediate SQLite DBs (transformer = default, free/local)
climafactskg process --classifier llm --concurrency 4   # same, via the LLM engine instead (--preset/--provider/--model/--preclassifier|--no-preclassifier override the xplainnlp-nslp preset, whose default is a local LM Studio model with the gate off)
climafactskg build                                      # assemble data/climafacts_kg.ttl from the DBs, auto-validates the output
climafactskg validate                                   # re-check an existing data/climafacts_kg.ttl parses and meets sanity thresholds
climafactskg classify "some claim text" --classifier matcher
climafactskg serve                                      # SPARQL endpoint over the built graph
climafactskg export
climafactskg eval context v2                             # build the review-context sidecar for an eval dataset (v1|v2; --force rebuilds)
climafactskg eval run eval.toml [--dry-run] [--yes] [--report]   # benchmark what a config file names (see eval.example.toml)
climafactskg eval report data/eval_runs/<run> [<run> ...] [--out report.html]   # HTML report from saved benchmark runs
```

CI (`.github/workflows/ci.yml`) runs `uv sync --all-extras --locked`, then `ruff check`, `ruff format --check`, and `pytest tests/` on every push/PR to `main`. `--locked` fails if `uv.lock` is out of sync with `pyproject.toml`.

Pre-commit hooks are configured (ruff format/check, `uv-lock`, toml/yaml checks, end-of-file/trailing-whitespace fixers, conventional-commit-msg linter) but only the `pre-commit` stage installs by default — run `pre-commit install --hook-type pre-commit --hook-type commit-msg` to also get commit-message linting locally. Two gotchas: pre-commit refuses to run while `.pre-commit-config.yaml` has unstaged changes (commit it on its own first), and `end-of-file-fixer` rewrites the final newline of the generated `data/climafacts_kg.ttl`, so the first commit attempt after a rebuild fails — just `git add` the file and commit again.

## Releases and commits

Releases are fully automatic: `.github/workflows/semantic-release.yml` runs on every push to `main`, and `python-semantic-release` (pinned to v10 in the `dev` dependency group, run via `uv run --no-sync`) bumps `project.version`, runs `build_command` (`uv lock && git add uv.lock && uv build` — the relock keeps `uv.lock` valid for `--locked` CI), splices a new section into `CHANGELOG.md`, commits, tags, and creates the GitHub release with the wheel/sdist plus `climafacts_kg.ttl/.rdf` and `cards.ttl/.rdf` and a graph-stats table. It then triggers the GH-Pages workflow.

- Commits must follow Conventional Commits. `feat` triggers a minor release, `fix`/`perf` a patch; `build`/`chore`/`ci`/`docs`/`refactor`/`style`/`test` never release. Commit messages become CHANGELOG entries verbatim, so write them for readers of the changelog.
- Do not add `Co-Authored-By` (or any tool-attribution) trailers to commits — they land in `CHANGELOG.md`.
- Don't edit `CHANGELOG.md` by hand. `[tool.semantic_release.changelog] mode = "update"` splices new releases in at the `<!-- version list -->` marker and leaves existing history alone; keep that marker and keep the mode explicit (v9 defaulted to full regeneration from git history, which would overwrite the backfilled entries).
- Committing a rebuilt `data/climafacts_kg.ttl` as `fix(data):`/`feat(data):` is what ships new data in a release.

## Architecture

Pipeline stages, each decoupled via a `preserve` SQLite DB as the boundary:

```
collectors/ (fetch + classify) -> preserve SQLite DBs -> builders/ (assemble RDF) -> data/climafacts_kg.ttl -> endpoints.py (serve)
```

- **collectors/** fetch raw data (`skepticalscience.py` scrapes SkS myth/rebuttal/glossary pages; `cimplekg.py`/`climatesensekg.py` query external SPARQL endpoints) *and* run CARDS classification inline via `collectors/utils.py:batch_classify_cards_category` before writing back to the DB. `cimplekg.py` and `climatesensekg.py` each have their own `fetch_claims`/`process_claims`/`classify_claims`/`process_all`, but the latter three are thin wrappers delegating to `collectors/utils.py`'s shared `process_claim_reviews`/`classify_claim_reviews`/`process_all_claim_reviews` — declared explicitly there as the contract any SPARQL ClaimReview source (`rev`/`date_published`/`text` columns) can reuse. A source whose SPARQL query can't produce that shape should write its own `process_claims` rather than forcing the fit.
- **classifiers/cards/** implements three interchangeable CARDS classifiers behind the same `classify`/`classify_batch` shape: `matcher.py` (spaCy + Jaccard similarity), `transformer.py` (two-stage HuggingFace: ClimateBERT binary gate + 18-class taxonomy model — the default engine for `process`, free/local, but needs the `transformer` extra since it imports torch/transformers directly — those imports raise a clear `ImportError` pointing at the extra if it's not installed), `llm/` (pydantic-ai structured output with per-provider presets, optional ClimateBERT pre-filter, `preserve` SQLite result cache — opt in via `--classifier llm`, core-installable). `pydantic-ai`/`openai` are core deps (not optional extras) since the LLM engine is a first-class alternative, not a fallback.
  - `batch_classify_cards_category` accepts a `cache_path` (Preserve SQLite file). Passing the *same* path for multiple sources — as `climafactskg process --cache-path` does by default (`data/cards_classification_cache.db`, shared across CimpleKG, ClimateSenseKG, and SkS arguments) — means identical claim/argument text is classified once, not once per source. `CARDSClassifier` (transformer) and `CARDSLLMClassifier` both cache through the shared `cache.py:ClassificationCache` (get-or-compute keyed by `hash(fingerprint|key)`, generic over the cached value via `serialize`/`deserialize` and over which computed values get written back via `should_cache` — the LLM classifier uses this to skip caching per-item failures). The LLM cache key covers provider, model, sampling settings and a hash of all four prompt templates (system and user, with and without context), so editing any template starts a fresh cache; `request_timeout` (seconds, not part of the key) cuts a stalled provider call off, and timeouts and dropped connections are retried like transient HTTP errors (open-weight models on OpenRouter have call latencies from 2 s to 6 min); `ClassificationCache` reads entries written before the shared cache (value stored under `output`), and `count_cached` counts hits without computing anything (used by the `eval run` plan). `CARDSLLMClassifier` holds two `ClassificationCache` instances (preclassifier gate, main LLM output); `CARDSMatcher` has no cache (cheap enough not to need one).
  - `classifiers/cards/base.py:CARDSClassifierBase` is the shared `classify(text, context=None)`/`classify_batch(texts, contexts=None)` interface all three engines implement — `context` is joined into the text (`f"{text}\n\n{context}"`) for matcher/transformer, or routed to a separate context-aware prompt template for the LLM engine. A `contexts` list whose length differs from `texts` raises `ValueError` in every engine (the zip-based ones via `strict=True`, the index-based LLM engine via an explicit check).
  - `builders/provenance.py` turns the stored `cards_category_classifier` tag into `schema:AssessAction` / `schema:SoftwareApplication` nodes (`:classification_<md5 of the tag>`, `:model_<md5 of the model id>`, one `schema:object` per labelled review) next to the unchanged `schema:about` links; a tag that does not name a model (the bare preset names older runs wrote) is skipped, never guessed. The LLM tag is now `<preset>|<provider>/<model>[+<gate model>]`, built from the classifier's real `provider`/`model`/`preclassifier_model`. Keep it additive: tests assert every triple of the untagged graph is still in the tagged one.
  - `batch_classify_cards_category`'s `cards_category_classifier` provenance field means different things per engine: an LLM preset name (e.g. `"xplainnlp-nslp"`, or `"xplainnlp-nslp|openrouter/google/gemma-4-31b-it"` when `process` overrides the provider/model via `llm_options`) for `classifier_engine="llm"`, or `TRANSFORMER_CLASSIFIER_ID` (`"transformer:<binary model>,<taxonomy model>"`) for `"transformer"`. Presence of this field — not its value — is what marks an entry as already-classified; switching a stored entry from one engine's tag to the other forces reclassification on the next run without `--force`.
  - `cards/__init__.py` lazily loads `CARDSMatcher`/`CARDSClassifier`/`CARDSEvalsAdapter`/`optimize_prompt` via `__getattr__` so that importing the LLM classifier alone does not pull in spaCy/transformers/torch/gepa. Preserve this when adding new classifier engines.
  - `classifier.py`'s `classify_batch` returns `None` (not a raised exception) for any item that still fails after retries, so a single bad item never discards the rest of a batch's successful results. `collectors/utils.py` relies on this: `None` categories are left un-written so the item stays pending for a future run. `transformer.py`'s `classify_batch` has no such per-item failure mode (mini-batched, but all-or-nothing per chunk).
  - Both engines compute a relatedness signal (`CARDSOutput.is_climate_related` for LLM, the binary-gate prediction for transformer) but discard it into a single collapsed `"0"`/`"0_0"` code — see the `project-relatedness-vs-category` memory note if working on eval/optimization accuracy.
  - **Eval datasets and review context** (`datasets.py`/`eval.py`/`evaluators.py` implement the eval pipeline against annotated ground truth): `nslp_dataset()` (HuggingFace ClimateCheck) and internal `climatesense_dataset_v1()`/`v2()` (Google Sheets/Drive annotations, reconciled via majority voting; annotators fill `cards_level1/2/3` as `"[5_1_1] Description"` — the bracket prefix is stripped by regex before voting, and depth-3 annotations are projected to depth-2 since the classifier only outputs depth-2). Review context for the ClimateSense datasets is prepared by `cards/context.py` (deterministic, LLM-free): `build_climatesense_context("v1"|"v2")` writes a sidecar `cards_annotations_context.csv` next to each consensus CSV (local annotation input CSVs for v2, chunked CimpleKG `VALUES` queries for v1's CimpleKG claims — 20 URIs per GET query, a pause between chunks, retry with backoff on HTTP 429/5xx, since the endpoint answers 414/429 otherwise; quotes have no review), and the dataset loaders join it in when you opt in (`climatesense_dataset_v2(with_context=True)` for the default sidecar, or `context_path=...`; a plain call stays claim-only, exactly as before) and run `select_context` (sentence-based, drops claim restatements, verdict fragments and AFP-style page boilerplate, `max_context_chars=800`). `evaluate(..., use_context=False)` is the like-for-like run; `benchmark_configs` runs each dataset with and without context (`context_modes`) and reports `n_with_context` per row, since only some datasets/cases have context (v1 climate-only: 5 of 153, v2: 143 of 143). A `"with"` run where fewer than `min_context_coverage` (default 0.5) of the cases carry context logs a warning: it mostly reflects claim-only classification. For a paired with/without comparison on the same cases, load the dataset with `only_with_context=True` (applied before `limit`; needs `with_context=True` or a `context_path`). Cases without context are handled gracefully by the LLM engine (it picks the plain or the context-aware prompt per item), so mixed datasets are valid to run; the caveat is only how to read the score. The classifier's own optional `max_context_chars` (default `None`) hard-slices context mid-sentence, so leave it unset for context runs.
  - **Eval scoring** (`cards/scoring.py`, used by `benchmark_configs`, the per-case evaluators and everything built on them): a failed prediction (`None`, the LLM engine's "still failed after retries") is a **wrong answer** that stays in every denominator, reported as `n_failed` (with `exact_answered` for the answered-only score); labels are folded to depth 2 on both sides so they are one class (`"0"` == `"0_0"`, `"1"` == `"1_0"`, a depth-3 matcher id `"2_1_1"` == `"2_1"`); exact = prediction is any acceptable gold label, hF1 = hierarchical F1 against the closest gold label; the F1 family charges a hit to the prediction and a miss to the closest gold label, micro-F1 is plain accuracy over every label that occurs (failures included), macro/weighted average over the gold classes that were charged or predicted at least once (so neither predicted-only classes nor classes that only appear as a second option in tied gold sets add zero-F1 entries). The summary also reports `not_related_rate` (share of answered predictions that say "not climate" — about 28% for gpt-4o-mini on v2, so most errors are the relatedness gate, not category confusion), `exact_unambiguous`/`n_unambiguous` (gold sets with a single label; v2 has ties in 46% of cases, so exact match is lenient), `baseline_exact` (best constant label) and a bootstrap interval on depth-2 macro F1 (`d2_macro_f1_lo/hi`). Gold sets can contain `0_0` through annotator ties ("not related" is then an accepted answer).
  - **Saved runs and reports:** `benchmark_configs(..., save_dir="data/eval_runs")` saves each run (`run.json` metadata incl. git commit, tidy `cases.csv` with one row per case/config/context mode, `summary.csv`) under a timestamped directory and attaches its path as `df.attrs["run_dir"]` (nothing is saved without `save_dir`; a failed save only logs a warning); the summary carries 95% bootstrap intervals (`exact_lo/hi`, `h_f1_lo/hi`, deterministic, over cases — with ~140 cases differences of about 4 points are noise). `print_benchmark` is compact by default (fits 80 columns, config/dataset labels shortened in the middle so labels sharing a prefix stay distinct, no `Ctx#` column — `wide=True` has it, `value±half-width`, dashes when nothing was evaluated, failures printed as one line each under the table, `wide=True` for every column incl. Error) and `print_context_effect(cases)` shows the paired none-vs-with effect on the cases that carry context (fixed/broken/unchanged) with a 95% bootstrap interval on the delta and an exact two-sided McNemar p-value (`mcnemar_exact`, on the discordant cases only); `compare_configs(cases, baseline)` does the same for every other config against a baseline on the cases both answered, and `eval report` adds a "Model comparison" section (`--baseline CONFIG`, default: the first config). The p-values are not corrected for the number of comparisons. On v2 gpt-4o-mini, context gives 10 fixed vs 21 broken: delta -0.077, interval [-0.154, 0.000], p = 0.071 — suggestive, not significant at 0.05. `climafactskg eval report` renders one or more saved runs into one self-contained HTML file (layout: with one benchmark the standard sections directly, with several an `_overview` matrix then one `<section class="benchmark">` per benchmark built by `_benchmark_body` with `placeholders=True`, so every benchmark lists the same headings in the same order and `_demote` shifts the headings down a level; the charts are always `ranked_bars_svg` (same chart for every benchmark), the Overview scores every benchmark on `exact_category`, size plots share one x axis (`size_range`), and `_size_section`/`size_scatter_svg` plot result against model size when two or more configs have `size_b` (read by `runs.model_size_from_id` from the model id, or set per classifier as `size_b`/`active_b` and saved in `run.json`'s `configs`; no new dependency, hand-built inline SVG; generated "At a glance" bullets worded by `report._verdict` — significant at 0.05, or "within noise" — and a collapsible glossary first, then the comparison table kept to the core columns with the secondary numbers under Reliability, then grouped SVG bar charts with error bars, context effect, cases changed by context; inline SVG, no JS/CDN, light and dark; built with plain strings, no new dependency; `data/eval_runs/` is git-ignored).
  - **Narrative detection and `category_scores`** (`scoring.relatedness`, `is_not_climate_gold`; the columns are `rel_*`, the user-facing name is "Narrative detection" because code `0_0` means no denial narrative, not strictly "not climate"): ClimateSense loaded with `climate_only=False` (v1: 245 of 398 pure `0_0`, v2: 134 of 277) and NSLP test (124 of 172) hold documents whose gold is exactly `0_0`. `benchmark_configs` always fills `n_not_climate` and `rel_precision/recall/f1/fpr` for them (positive class = has a category, a wrong category still counts as detected, a failure is wrong either way, tied gold sets containing `0_0` are skipped; NaN without negatives). `category_scores` (`[run] category_scores` in the config) decides which cases the category scores cover: `"all"` (default: the behaviour before narrative detection and in 2.2.0; 2.3.0 briefly used the split, so NSLP numbers match 2.2.0, not 2.3.0) scores every case; `"narrative_only"` drops the pure-`0_0` cases from `n_cases`, exact/hF1/F1 and `cases.csv` (and is recorded in `run.json`). `_across_benchmarks` averages the context-free per-benchmark scores (unweighted mean, models run on every benchmark only) into ranked charts and size plots; `exact_detected`/`n_detected` and `hf1_detected` (+ `_lo/_hi`, from `scoring.detected_category_scores`/`detected_category_hf1`) are the CARDS category on its own: exact match on cases whose gold has a category and where the model detected a narrative (answered a category, not `0_0`, not a failure); a missed narrative is charged to relatedness (`rel_*`), not here, and the report's Overview, size plots and charts show these two scores apart. `exact_category`/`n_category` are always computed (exact match over the cases that carry a category, equal to `exact_match` without pure-`0_0` gold), and the report shows that column when a dataset has `0_0` documents; the report's At a glance also flags a config whose exact match is at or below `baseline_exact`, and the model comparison lists the baseline as a row. `print_benchmark`/the HTML report add a Narrative detection table only when `rel_f1` has values. `evaluate(classifier, dataset)` is just `benchmark_configs` with one config and one dataset (prints the benchmark table, returns its one-row DataFrame, raises `RuntimeError` if the classifier raised), so it scores exactly like `eval run`; the old pydantic-evals report evaluators and the `python -m ...cards.eval` demo block were removed, and `eval.example.toml` replaces that hardcoded model list. The LLM engine's "related but no category" case is still stored as `0_0` and counts as a miss.
  - **`eval run` config** (`cards/runconfig.py`): `eval run CONFIG.toml` is the one-command way to benchmark: a pydantic-validated (`extra="forbid"`) TOML with `[run]` (save_dir, context_modes, min_context_coverage, category_scores), `[defaults]` merged under each `[[classifiers]]` (LLM-only keys and `options` are not inherited by transformer/matcher engines; a non-LLM classifier that sets them itself is an error; TOML has no null so an option `"none"` becomes `None`) and `[[datasets]]` (optional `label`, so one dataset can run under several settings). It builds datasets first to print the plan, `--dry-run` stops after the plan (paid LLM classifiers are built with `peek=True`, i.e. without the ClimateBERT gate, only to count their cache hits for free; free classifiers are never built and no model is called), and a run with paid classifiers (LLM provider not ollama/lmstudio; an unset provider counts as paid) asks for confirmation unless `--yes`. The config text is copied to `config.toml` in the run dir; `--report` writes `report.html` there.
  - **Caveats:** The GEPA optimizer (`build_mixed_trainval`) always loads the ClimateSense datasets with `with_context=False`, so it trains claim-only regardless of sidecars. The gold labels were annotated from claim text only (the annotation sheets have no review column and the annotator guidelines contain no instruction to consult reviews), so a with-context run measures agreement with claim-only labels, not accuracy against a context-informed truth. The transformer engine slices `text + context` to 256 characters, so context is only meaningful for the LLM engine.
  - `build_mixed_trainval(mix, climate_only=True, shuffle_seed=None)` keeps the old behaviour by default (file-order slices of the category-only ClimateSense documents, so the prompt never sees a `0_0` document); pass `climate_only=False` to train on the "no narrative" documents too, and a `shuffle_seed`, because the files are not in random order (the first 150 cases of `climatesense_dataset_v1(climate_only=False)` are 97% `0_0`, the rest 40%). `build_heldout(mix, ...)` with the same arguments returns the cases left over, to score the original and the tuned prompt on data the optimiser never saw (the NSLP optimiser data is its `train` split, the benchmark's is `test`).
  - The `xplainnlp-nslp-tuned` preset is `xplainnlp-nslp` with a GEPA-tuned system prompt (`XPLAINNLP_NSLP_TUNED_SYSTEM_PROMPT`, kept verbatim including the `{"instruction": ...}` JSON wrapper the optimiser returned, because the unwrapped text lost most of the measured gain). It is experimental and opt-in by name: on gemma-4-31b it trades false alarms for recall and did not transfer to ministral-14b; the preset's docstring has the numbers and caveats.
  - In `CARDSEvalsAdapter.evaluate`, a case whose model call raised is dropped by pydantic-evals from `report.cases`; the adapter reads results back by case name so the failure keeps its slot as a wrong answer (output `(call failed)`, score 0, left out of the reflection feedback) instead of shifting every later score onto the wrong claim.
  - `optimization.py` runs GEPA-based prompt auto-tuning; batch cases carry `(index, claim)` tuples (not bare claim text) so duplicate claim strings in one optimization batch don't collide on context lookup.
- **builders/** assemble the final RDF graph and are intentionally decoupled from collectors/classifiers — they only import `climafactskg.utils`, reading exclusively from the `preserve` DBs. `climafactskg.py` is the main graph builder (merges SkS arguments, `cards.ttl`, CimpleKG, and ClimateSenseKG mappings — the latter two share the same `generate_cimplekg_mappings()` function since they're produced by identical collector code); `sksreferenceskg.py` builds the scholarly-reference/citation subgraph.
  - `generate_climafactskg_base` builds each SkS article into its own temporary `Graph` and merges it only if the whole article succeeded, so an exception part-way (e.g. a page with no `what_the_science_says`) drops the article instead of leaving a half-built `sc:ClaimReview` in the output. `ignore_urls` matches regardless of `http`/`https` (the SkS DB stores some pages as `http://`).
  - Every stored URL becomes an IRI through `builders/utils.py:safe_uriref`, which also strips presigned-URL credentials — route any new URL emission through it.
- **parsers/skepticalscience.py** turns scraped HTML into structured fields consumed by the collector/builder. `climafactskg/utils.py`'s `strip_credential_query_params` strips known cloud-storage presigned-URL credential params (`AWSAccessKeyId`, `X-Amz-*`, etc.); `parse_apa_citation_html` applies it to extracted citation links and `safe_uriref` applies it again at graph-build time, so URLs already stored in a DB before the parser learned to strip them still can't reach the published graph. A real embedded AWS key was found in scraped data (and shipped in a release) once — keep both layers when touching link extraction or URL emission.
- `climafactskg validate` (and an automatic call at the end of `build`) parses the output graph and checks it's non-empty with at least one `sc:ClaimReview` node — catches build/serialization breakage (e.g. malformed Turtle from an unescaped literal) immediately rather than shipping a broken `.ttl`.
- Test coverage (`tests/`, 522 tests, all offline — no network, API key, or model download) covers the pure/stateless pieces plus the builders' core behavior: `taxonomy.py`, `evaluators.py`, `matcher.py`'s Jaccard math and batch/context handling, `utils.py` (SPARQL parsing, citation detection), `stats.py`'s graph validity checks, `sksreferenceskg.py`'s private regex helpers, `cache.py`, `collectors/utils.py`, `builders/utils.py` (`new_graph`, `safe_uriref` credential stripping), `builders/climafactskg.py` (cards-category exclusion, atomic per-article build, scheme-insensitive ignore list), `builders/cimplekg.py`, the `collect` CLI, the LLM classifier's input validation, `cards/context.py` (review-context selection and sidecar building), `cards/runconfig.py` and the `eval` CLI (schema, defaults merge, paid guard, stubbed benchmark), `cards/runs.py` and `cards/report.py` (saved runs, intervals, paired context analysis, HTML report), the ClimateSense dataset loaders' context join, and `evaluate`/`benchmark_configs` context modes. The LLM classifier's batch failure isolation, result caching and context routing are tested with the LLM call stubbed, but its real async/retry behaviour, the real collectors' network paths, and the rest of the eval/optimization pipeline remain untested; be extra careful with manual verification when touching those. A cheap live check of the LLM path is a small `CARDSLLMClassifier(provider="openrouter", model="openai/gpt-4o-mini", cache_path=<scratch db>)` batch (a few cents), followed by `evaluate(clf, nslp_dataset(limit=8))` — `.env` defaults `CARDS_LLM_MODEL` to a pricier model, so override it explicitly for tests.

## Model selection report

`docs/model-selection.md` (with `docs/model-selection/`: charts, `results.csv`, and `make_plots.py` / `gate_and_weights.py` that rebuild them from a saved `eval run`) records how the 32 classifiers were compared and the recommendations the README summarises. Its ranking uses a balanced score, `0.75 x category accuracy + 0.25 x (1 - false-alarm rate)`, pooled over the three benchmarks; plain exact match is a poor ranking there because 59% of the documents carry no narrative. When the suite or the weights change, rerun the scripts on the new run and update the report and the README table together.

## Style

- Google-style docstrings (ruff `pydocstyle` convention), 120-char line length.
- Ruff handles both lint and format; run `ruff check --fix` before considering a change done.
- Use `zip(..., strict=True)` for lists that must line up one-to-one (texts/contexts, items/outputs, cache misses/results) so a length mismatch raises instead of silently truncating or misaligning labels. `strict=False` is only for independently scraped sequences that may legitimately differ (the two SkS footnote selectors in `parsers/skepticalscience.py`).
- Prefer deferred/lazy imports for heavy optional dependencies (spaCy, transformers/torch, gepa) — see `cards/__init__.py` and `cli.py`'s per-command imports — so that commands not touching those paths stay fast and don't require the optional extras to be installed.
